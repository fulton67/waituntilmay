# OSTAD VISUAL BIBLE — how the graphics are built and why they work

Unattended. Same rules as the other Ostad runs: never ask, log decisions in `research/ostad/bible/DECISIONS.md`, resume from `research/ostad/bible/TODO.md`, push to main as soon as each part is measured and committed. Requires both refs passes to be finished: `research/ostad/refs/refs.json`, `procedures.json`, `sources.json`, the images in `research/ostad/refs/img/`, and from pass 2 `motion.json`, the downloaded animations/frame grabs, `models.json` and the base scene in `research/ostad/3d/base/`. If either isn't finished, finish it first (OSTAD_REFS.md, then OSTAD_REFS_2.md).

## Why this exists

Every procedure Ostad performs or talks about gets its own video, made by Naim, in a visual language that is exclusively Ostad's. Nothing in the refs library is ever reposted or re-cut into his content; it is the standard his graphics are measured against. This document is the thing that makes "exclusively his" repeatable: the rules, the conversion method, and the templates.

## What this is

A design bible in the sense of a film production bible or an early video-game design document: the complete, written, rule-level description of a visual world. Not a moodboard. Every statement is either a rule ("the dermis is always drawn as…"), a measurement ("median line weight across 212 cross-sections is 1.6 px at 1000 px width"), or a mechanism ("RF energy is depicted as a heat gradient because…"), with the reference images that justify it. The reader is a designer or animator who has never seen a medical graphic and has to produce one tomorrow that sits next to the best of the refs library without looking out of place — and, in the final chapter, one that is unmistakably Ostad's.

Method is the one used for the Felix Luke brand bible (REA/Lexicon; locate it with the same `find` as run 1 and read it first so the structure and depth match): read the corpus in full, measure it, then write. Here the corpus is images, so "reading" means looking at every image and "measuring" means running analysis over them.

Output: `research/ostad/bible/BIBLE.md` (long — 15,000–30,000 words is normal for this), a figures folder `research/ostad/bible/fig/` of the measured plates and your own schematic diagrams, and a rendered **Bible** tab on `/ostad` (same styling as run 2; one chapter per page, figures inline, every rule linked to its evidence images in the refs library).

## The quality bar

The target look is the manufacturer MOA film and the studio reel: real 3D geometry, matte subsurface-scattered skin layers, a soft studio light, a camera that moves with intent, labels composited on top. Not AI-generated stills, not glossy pink blobs.

**The gold set is Naim's picks.** Read `research/ostad/refs/gold_picks.json` (exported from the Gold toggle on `/ostad/refs`; a zip of the same images may sit beside it). Those ids — stills and motion references — are the only evidence this document is built on; their `note` fields are instructions. If a procedure has no picks, fall back to that procedure's `gold: true` provenance set and say so in its entry. If the file is missing entirely, stop and write BLOCKED.md: the bible is not to be built without the picks.

**Everything is an overlay.** Ostad is on camera; the graphics sit on top of him. So every rule, template and conversion in this document assumes transparency: Blender renders with film transparent, delivered as PNG sequence with alpha plus WebM/VP9 alpha; Flora stills are generated on a flat, single, keyable colour (specify it in chapter 6 — not green if the palette uses green) and keyed in comp; Seedance clips the same, with the constraint block forbidding background change so the key holds; labels and leader lines live on their own layer. Chapter 4 gets a section on how an overlay reads over a talking head: where in the 9:16 frame it sits, how much of him it may cover, how it enters and leaves. If something quarantined as `ai-generated` is cited, that is a bug. The whole point of this bible is that Naim's output lands at the studio bar, so every rule is written at production level — numbers a Blender scene can be set to — not as adjectives.

## Form: write it like the Doom Bible

The depth reference is Tom Hall's Doom Bible (id Software, rev .02, 28 Nov 1992) — a copy is at `research/ostad/refs/DOOM_Bible.pdf` if Naim drops it there; if not, you know the document. Match its discipline, not its subject:

- **Cover with a revision number and date.** This is rev 0.1. Every regeneration bumps it and keeps a one-line changelog at the front.
- **Styles first, then everything in those terms.** Chapter 5b defines the manufacturer looks and chapter 6 defines the Ostad look the way Tom defines Old / UAC / Mine / Demon: a name, a reference, five lines. Every later entry describes its graphics by naming a style and the deviation ("Ostad standard, cutaway variant, no labels until beat 3"), never from scratch.
- **Identical template per procedure, no exceptions**, even where a section is thin: Story (what he says about it, from transcripts) · Actors (the anatomy and agents involved) · Unique Bits (what only this procedure needs) · Shot List · Asset Manifest · References. A procedure with no gold refs still gets the template with "none yet" in the slot.
- **Asset manifests with V / D / N priority.** For every procedure, every shot, every 3D element, every label, every effect, every sound/music cue, every lower-third, marked **V** vital (the video can't ship without it), **D** desired, **N** non-vital. Then one master manifest across all 97 procedures, sorted by how many procedures need the asset — that is the production schedule.
- **Margin symbols.** Use a fixed set and define them on page 1: ⊗ hero frame (the one still that sells the video), ♠ a detail nobody will ask for but should be there, ⚠ claim a physician must check before it's said on camera, ↻ an asset reused from another procedure.
- **Appendices that run the team:** A. Glossary of house vocabulary (every term we coined, with Tom's bluntness); B. File naming and folder layout; C. Utilities — exact invocations for every step of the pipeline (the Flora canvas setup, the Seedance call via OpenRouter with the constraint block, the Blender headless render commands, the ffmpeg frame-grab, the publish command for `/ostad`), each with its parameters listed the way Lumpy and WadLink are; D. Approved language — the sentences about each procedure that are safe to say and the ones Ostad himself avoids (from his transcripts), like the press release section: copy from here, don't improvise; E. Random Extremely Important Info — contacts, the practice's address and hours, who signs off on a claim, where the gold refs live, where the base scene lives; F. Known failure modes — every generation and render problem seen during the run, with the fix or "unfixed".
- **Tone.** One person writing to a team that has to build the thing tomorrow. Short declaratives. Opinions allowed ("Otherwise, why is it there?"). No marketing voice.

## Part A — measure the corpus

Run over every **gold** image and every downloaded animation in the refs library and write `bible/measurements.json` plus one plate per measurement in `bible/fig/`:

1. **Palette.** k-means (k=8) per image, then aggregate by `type` (cross-section, MOA, injection-map, surgical-steps, 3D-anatomy, device) and by anatomical layer where labels identify one. Report the modal colours for epidermis, dermis, hypodermis/fat, muscle, SMAS/fascia, bone, blood, nerve, device energy (RF, laser, ultrasound, EM), filler, toxin, collagen. Note which conventions are near-universal (fat is yellow in N% of images) and which split.
2. **Line & edge.** Edge density, dominant stroke weight relative to image width, outline vs no-outline ratio, per type and per source kind (manufacturer vs journal vs studio).
3. **Composition.** Where the subject sits, aspect ratios, cross-section orientation (skin surface at top in N%), viewing angle of 3D renders, how much of the frame is label text, label placement (leader lines vs direct), number of labels per image.
4. **Typography.** Where readable: sans vs serif share, case, weight, label-to-image scale. Name fonts only where you can confirm them.
5. **Depth & rendering.** Flat vector / shaded vector / soft 3D / photoreal 3D share, per type and per year where a date is known. Lighting direction in 3D renders.
6. **Narrative devices.** Before/during/after triptychs, zoom insets, arrows, time-lapse frames, "activated" glow states, ghosted layers, cutaway windows — count their use per type.
7. **Source signatures.** For each top-10 source, what makes its images recognisable in three measurable terms.
8. **Render forensics (from the animations).** From frame grabs of the gold animations, estimate and record: apparent focal length (wide vs long — measure perspective convergence on straight edges), depth-of-field use, light direction and softness (shadow edge width), specular level on skin layers (near-zero in the good ones), subsurface look (edge translucency), background type (gradient/solid/none), frame rate feel (24/30/60), easing of camera moves (count frames to settle), and the duration of each beat. These are the numbers chapter 6 turns into a Blender setup.

Each plate: one claim, labelled, schematic, no node graphs. Look at every plate after generating it and fix anything unreadable.

## Part B — write BIBLE.md

Chapters, in order. Every chapter cites refs by `procedure_id/hash` so the rendered page can show them.

**0. How to use this document.** One page.

**1. The world.** The body as the setting. The canonical cross-section of the face and skin: epidermis, dermis, hypodermis, superficial fat compartments, SMAS, deep fat, muscle, periosteum, bone; the neck; the body sites he treats. For each layer: what it is in one sentence, how the corpus draws it (colour, texture, thickness relative to the others, whether it's labelled), and the rule we adopt. Include the facial danger zones and the named fat compartments as the "map" of the world, drawn as your own schematic plate. Include the aging model the whole industry draws from (bone resorption, fat descent, ligament laxity, skin thinning) because every "why this treatment" graphic is a variation on it.

**2. The physics, and how each is drawn.** One section per energy or agent: neurotoxin, HA filler, biostimulators (Sculptra, PRFM, exosomes), ablative and non-ablative laser (MTZ columns), picosecond laser (shockwave/fragmentation), RF and RF-microneedling (heat gradient, needle depth), HIFES/EM (muscle contraction), micro-coring (Ellacor), threads, lipolysis, Mohs (layered excision and mapping), excision/suture, PDT, peels, microneedling/micro-infusion. For each: the real mechanism in plain language; the visual metaphor the industry has converged on and why it reads (heat = orange gradient, laser = vertical columns, toxin = cut signal, filler = volume fill, collagen = growing fibre mesh over time); the measured evidence from Part A; the rule we adopt; the common mistakes seen in weak refs.

**3. The procedure lexicon.** One entry per procedure in `procedures.json`, grouped by category, every entry on the fixed template from the Form section: **Story** (what he says about it in his own transcripts — quote his actual phrasing, under 15 words — and the claim the video makes); **Actors** (the layers, structures and agents involved, by their chapter-1 names); **Unique Bits** (what only this procedure needs: a cannula, a thread, a Mohs map, a specific effect); **Shot List** (cross-section, MOA, map, before/during/after, device — each shot named by style + deviation, with ⊗ on the hero frame and ⚠ on any claim); **Asset Manifest** (every element, V / D / N, ↻ where reused); **References** (the best 3–6 gold refs with one line each on why, and the motion refs with their beats).

**4. The grammar.** The rulebook, derived from Part A: palette (a fixed hex per layer and per energy), line system, label system (leader lines, placement, max labels per frame, casing), composition (orientation, margins, where the surface sits, zoom-inset conventions), 3D rendering standard (material, lighting, angle), motion (the beats of a MOA animation: establish → zoom → activate → effect → result; durations measured where the corpus has animation stills or videos), vertical 9:16 adaptation rules for shorts, on-screen text system for the videos (what the explainer graphic looks like when it's a lower third vs a full-frame cutaway).

**5. How they are made.** The production reality, researched (web search; cite): how studios like Nucleus, AXS, TVASurg and manufacturer agencies actually build these — reference gathering (surgical observation, cadaver atlases, Cotofana-style layered dissection), modelling (ZBrush/Blender/Cinema 4D, Complete Anatomy and Zygote as base meshes), illustration (Illustrator, Procreate, Photoshop), animation (After Effects, Blender, C4D), review by a physician; typical timelines and costs; licensing norms. Then **Naim's pipeline**: how to produce each shot type with his stack (Blender → R3F or video; Illustrator/SVG; image-gen with Nano Banana for stills using the grammar in chapter 4 as the prompt — write the actual prompt templates, fresh standalone prompts, simple, one per shot type) and what each takes in hours.

**5b. The manufacturer bibles.** One mini-bible per maker whose material dominates the refs library — expect InMode, Solta, BTL, Candela, Cutera, Cynosure, Allergan, Galderma, Merz, Evolus, miraDry — plus one per studio that's identifiable (Nucleus, AXS, Random42). Each is built from that maker's stills in `refs.json` AND its animations in `refs/motion.json` (pass 2), and follows the same structure every time so they're comparable: palette (measured hex per layer and per energy), render style and lighting, line and label system, camera language (which moves they use, in what order), the beats of their MOA animation (establish → zoom → activate → effect → result, with measured durations from the downloaded videos), how they visualise their specific energy, signature tells (three measurable things that make it recognisably theirs), and what they do badly. End each with a one-line verdict on what to take from them. This chapter is what the conversion method in chapter 7 draws from.

Add one entry that is a **render-look benchmark, not a maker**: Zygote Body (zygotebody.com). Study it from screenshots and screen recordings of the public viewer only — orbit it, peel layers, zoom — and measure the look: matte, lightly translucent materials; soft studio light with almost no specular; neutral gradient background; the orbit and layer-peel as the whole interaction language; label behaviour on hover. Never extract its models or textures; the meshes come from the open sources in refs pass 2. Naim has named this as the look he wants for the 3D side of Ostad's style, so chapter 6's render standard is defined against it.

**6. The Ostad house style.** The decisions. Starting from his site's existing visual language (crawl in CLIENT.md: logo, type, palette, photography) and the brand-bible's "clinical luxury" direction, fix: palette (map chapter-4 layer colours into his brand), type, line weight, render style, label voice, motion timing, the frame for 9:16, the on-screen text system, the before/after frame, the device shot. The 3D standard is written as a **Blender production spec**, in `bible/blender-spec.md` and as an actual `bible/templates/ostad_base.blend` built on the refs-pass-2 base scene: render engine and sampling; per-layer materials with exact values (base colour hex, subsurface weight and radius, roughness, specular, sheen) for epidermis, dermis, fat, SMAS, muscle, bone, vessel, nerve, product (HA, Sculptra, toxin), device metal, needle; the light rig (key/fill/rim positions, sizes, strengths, colour temperature); world/background; camera (focal length, sensor, DOF settings, the three standard framings: orbit establish, cross-section cutaway, macro at the needle tip); animation (fps, the standard easing curve, durations per beat from Part A); the energy effects as reusable node setups (RF heat gradient, laser columns, EM contraction, filler volume, toxin signal cut, collagen growth); label and leader-line style for compositing; output settings for 9:16 and 16:9. Every value is justified by a Part A measurement or marked as a judgment call.

Then the **hero shot**, built and rendered in this run: *injection into skin* — cannula or needle enters at the surface, camera pushes into a cutaway, the product deposits in the correct plane, the tissue responds, pull back to the face — 6–8 s, 9:16, rendered from `ostad_base.blend` with the spec above. This is the proof that the spec produces the studio look. Render it, look at every frame, fix what's wrong, render again; save the final MP4 and the frame grabs in `bible/hero/` and show it at the top of the Bible tab next to the three gold animations it was measured against. If the render is slow on this machine, drop resolution for iteration and render final at 1080×1920 in the background while you continue.

Produce the master templates as SVG in `bible/templates/`: cross-section master (face and body), injection-map master (full face with compartments), MOA master (energy in skin, with the energy layer swappable), surgical-steps master (three-panel), device master, lower-third and full-frame text. Then **do / don't** with paired examples from refs. Then a worked example: take three videos from `PLAN.md`, specify every graphic each one needs using the templates, and render them as SVG so the chapter ends with finished frames.

**7. The conversion: still → 3D render → motion.** The repeatable method. This is the chapter that gets used every week, so it is written as a procedure with checklists, not prose. Inputs are a flat reference still from the refs library (a DuckDuckGo/journal cross-section, injection map or MOA diagram). Outputs are (a) a rendered 3D-style still in the Ostad house style and (b) a 4–6 s 9:16 motion piece. Engine is the local Qwen image model in ComfyUI on this machine (port 8188, see the existing setup; use image-to-image / reference-conditioned generation — find which Qwen workflows exist in the ComfyUI install and use those), with Seedance via OpenRouter for image-to-video, and Blender + the base scene from refs pass 2 when the shot needs true geometry (orbit, cutaway, needle depth).

Sections:
- **7.0 The spec sheets.** No model training. The method is: the written description does the work. For **every** `gold: true` still and every beat-frame of the gold animations, write a spec sheet — `refs/specs/{image_id}.md` — at the depth of a film production bible: what the frame shows (subject, every layer visible and its order, the energy/agent and exactly how it's drawn), geometry (camera framing, focal feel, angle, where the cut plane is, scale), light (direction, softness, colour temperature, where the shadows fall), materials (per layer: colour hex from Part A, matte/translucent, how edges read), background, labels (what they say, where, leader-line style — and note that they'll be re-added in comp, so the generated frame is label-free), motion if it's a beat (what moves, over how long, easing), and three sentences on *why it reads* — what makes this frame legible. End each sheet with a **generation block**: a fresh standalone prompt, simple, one paragraph, that describes the frame to an image model so it could be reproduced nearly one-for-one — identify what's actually recognisable about the reference and keep that, change only what must change (Ostad palette, label removal). These sheets are the context Naim pastes into Flora alongside the gold image itself; they're also what chapter 7.3 and 7.4 read from. Render them in the Bible tab next to their image. Measure: every gold item has a sheet; sheets average ≥ 250 words; the generation block is under 120 words.
- **7.1 Reading the still.** Checklist to extract what the still actually encodes before anything is generated: layers present and their order, the energy/agent and how it's drawn, labels and what they claim, orientation, what's omitted. Write it as a short structured note; this note is what the prompt is built from, not the image alone.
- **7.2 Choosing the route.** Naim's pipeline is **Flora → Seedance**: the image model inside Flora.ai makes the frame from the gold reference plus its spec sheet; Seedance (via OpenRouter, the model already in use on this machine) animates it under constraints. That is the primary route for every procedure's graphics. **Blender** (`ostad_base.blend`, chapter 6) is the route only for the things generation can't do: anything the viewer orbits live in R3F, and any sequence where geometry must stay exact across many frames. Give the rule as a table with examples from the refs library.
- **7.2b The slop test.** A checklist any generated frame must fail to pass out of: readable, correct labels; one identifiable light direction; no edge glow without a source; layer count and order match chapter 1; anatomy consistent across frames of a sequence; specular on skin layers near zero; no "pink gloss". Anything that fails goes back or goes to Blender.
- **7.3 The image step (Flora).** How to set up the Flora canvas for this: the gold image in a reference node, the spec sheet's generation block as the prompt, the house-style block from chapter 6 appended (layer palette as hex, finish, lighting, background, aspect, "no text, no labels"). Prompts are fresh and standalone, simple, built from the 7.1 note; the rule from Naim's practice applies — identify what's actually recognisable in the reference and have the model copy it essentially one-for-one, changing only what must change (palette, label removal), not a loose interpretation. Record which image models inside Flora held the look best on the 12-prompt test set, and the reference-strength settings that worked. Include the failure modes seen (layers merging, text hallucinated, wrong orientation, pink gloss) and the fix for each. Labels are never generated; they're composited after.
- **7.4 The motion step (Seedance), with constraints.** Seedance prompt grammar, written as a constraint block that goes on every animation: exactly one camera move and one effect per clip; duration 4–8 s; 9:16; the Flora still as the @Image reference and the start frame; the first and last frames must match the still's anatomy (no new layers, no drift); the effect vocabulary per energy from chapter 2 (heat bloom, column appear, signal cut, volume fill, fibre growth, layer peel) with the measured beat durations from Part A; motion easing described in words the model responds to; "no text" always. Longer sequences are chained: each clip's last frame is extracted and becomes the next clip's reference, with the camera continuing. Record the Seedance settings that worked and the rejects, with why.
- **7.5 The Blender route.** When geometry is needed: which base scene, which layers, camera preset, effect primitive, export to GLB or render to video; links to the shot plans from refs pass 2.
- **7.6 QA.** Checklist a frame must pass before it goes on Ostad's channel: anatomically consistent with chapter 1, energy drawn per chapter 2, palette and labels per chapter 6, no claims a physician would object to (list the ones from his transcripts he is careful about), legible at phone size.
- **7.7 Worked conversions.** Do as much of it as can be done unattended: take 10 gold stills covering different types (cross-section, injection map, laser MOA, RF MOA, surgical steps) and different makers. For each: the spec sheet (7.0), the 7.1 note, the Flora-ready prompt package (reference path + generation block + house-style block) saved as a file Naim can paste, the Seedance constraint block, and the QA checklist pre-filled with what to check. Run Seedance only if a Flora output for that still already exists in `bible/conversions/{n}/flora/` (Naim generates those by hand in Flora; the run can't drive Flora). Save everything side by side in `bible/conversions/{n}/` and render the folder in the Bible tab as a before / prompt / after strip, with the "after" slot empty until Naim drops the Flora output in — the tab re-renders from the folder on the next publish.

**8. Master asset manifest.** All 97 procedures' manifests merged: one row per asset, columns for which procedures need it, highest priority among them (V beats D beats N), build route (Flora / Seedance / Blender / comp), status. Sorted by reuse count. This is the build order.

**Appendices A–F** as listed in the Form section. Then the index: every procedure → page; every source → what it's good for.
